# ZakiAlarm

ZakiAlarm is a Vietnamese, mobile-first alarm and sleep-journal frontend. Every
feature is free: no account, premium tier, payments or advertising. The UI keeps
the navy, mint, lavender and peach design language of the original frontend.

## Run

```bash
npm install
npm run dev
```

Open the local URL Vite prints. Opening `index.html` with `file://` will not run
the Vite modules correctly. For a production build, use `npm run build`; for
logic/route tests, use `npm test`.

## Functional areas

| Area | Behavior |
|---|---|
| Alarms | Create/edit/delete/duplicate/enable; 24-hour picker; repeat days and one-off alarms; skip next occurrence; one replaceable quick-nap countdown; nearest-alarm countdown. Quick naps stay outside the alarm list. |
| Alarm flow | Clock-based trigger while the page is active, ringing, configured snooze countdown and limits, ordered missions, five-minute wake-up check, and 15-tap emergency exit. Active snooze/check session resumes from its deadline after refresh. |
| Missions | Actual math, memory and exact-phrase checks; motion sensor shake where available; camera QR/barcode matching through `BarcodeDetector`; manually confirmed walk, squats and reference-photo missions. Each unsupported sensor flow offers a math fallback. |
| Music | Four basic synthesized alarms, three more synthesized melody styles, three bundled CC0 EDM/retro loops, and local music imports through IndexedDB. Sound picker includes search, categories, preview, volume, vibration and attribution. |
| Sleep | Bed/wake targets, elapsed session journal, report of actual recorded duration, history, seven-day average/bar display, and explicit 60-second microphone samples stored locally. The app does not infer sleep phases, pulse, sleep score or snore events. |
| Relaxation | Five Web Audio ambient sounds, search, category filter, favorites, volume and timed stop with optional ten-second fade. |
| Settings | Dark/light theme, three text scales, alarm readiness test, browser permission checks, export of settings/history and deliberate deletion of locally saved data. |

## Browser limits

An ordinary webpage cannot guarantee an alarm while its tab is closed, device is
asleep, audio is blocked, or the browser throttles timers. The readiness screen
offers a five-second audio test. Keep the page open with the device awake when
using it as an alarm. A native iOS/Android application would need OS alarm and
background execution APIs to provide reliable locked-device alarms.

Camera, microphone, motion and notification access require the browser/device
to support and grant those APIs. `BarcodeDetector` is not available everywhere.
Walking and squats use manual confirmation; reference photos are manually
compared. Microphone samples record for up to one minute while the page is open.
No AI sleep, snore or photo classification is claimed.

Alarm settings and history use localStorage. Imported tracks and microphone
samples use IndexedDB. These are local to the browser/profile/origin. JSON
export covers settings and session metadata; it does not include audio blobs,
and is not a restore file. Browser storage limits and private mode may prevent
saving; the UI shows a warning when localStorage fails.

## Audio provenance

The three bundled music loops are CC0, individually documented in
[`public/audio/ATTRIBUTION.md`](public/audio/ATTRIBUTION.md). Synthesized sounds
are generated by ZakiAlarm. No Alarmy audio was copied, and the bundled tracks
are not described as verified trending songs. Users may import their own
licensed audio files of up to 20 MB through the sound picker.

## Checks

`npm test` covers scheduling across midnight and day boundaries, one-off and
skipped alarms, form validation, response validation, local persistence,
escaping user content, all exposed screen routes, and empty-state rendering.
The local UI was manually checked for create/edit/save, filtering and selecting
CC0 music, memory/typing execution, alarm testing, snooze across a reload,
and sleep-session persistence/report/history.
